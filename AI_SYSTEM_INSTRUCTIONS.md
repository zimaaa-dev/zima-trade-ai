## ЧАСТЬ 1. Описание проекта, принципы работы и состав модулей

### 1.1. Концепция проекта
**ZIMA-TRADE-AI v4.0** — это автономный количественный (Quant) комплекс для высокочастотного анализа стакана ликвидности **L2-50**, парсинга новостных и сигнальных потоков (Telegram-каналы, RSS/CryptoCompare, Whale Alert), самообучения ансамбля ИИ-ботов в режиме реального времени и автоматизированного исполнения ордеров на **Bybit API v5** (Спот и Бессрочные USDT-фьючерсы) с резервными контурами OKX и MEXC.

### 1.2. Главные принципы работы («Железные законы системы»)

1. **Двухконтурный режим работы (Shadow Mode vs Live Mode)**:
   - **Режим 1 — Обучение (Shadow / Paper Forward-Testing)**: Никаких синтетических «рисованных» бэктестов без учета ликвидности. Даже в режиме симуляции ордера сводятся строго по живому стакану L2-50 с учетом сетевой задержки ($t_0 + \text{RTT} + 20\text{ мс}$), очереди лимитных заявок (`volume_passed > queue_ahead`), реального проскальзывания VWAP, комиссий Taker (`0.055%` вход + `0.055%` выход = `0.11%`) / Maker (`0.02%`) и ставок фандинга.
   - **Режим 2 — Боевой (Live Execution)**: Прямая отправка ордеров в Bybit API v5 с криптографической подписью `HMAC-SHA256` (`X-BAPI-SIGN`, `X-BAPI-TIMESTAMP`, `X-BAPI-RECV-WINDOW`).

2. **Неизменяемый процедурный Риск-Файрвол (`evaluateRiskFirewall`)**:
   Ни одна нейросеть, LLM или внешний сигнал из Telegram не могут напрямую отправить ордер на биржу в обход детерминированного ядра `evaluateRiskFirewall()`:
   - **Риск на сделку (1.5% Equity Cap)**: Максимальный убыток при срабатывании стоп-лосса (включая `0.11%` round-trip комиссию Taker) жестко ограничен `1.5%` от текущего капитала (`maxLossUsd = capital * 0.015`).
   - **Лимит маржи на одну позицию (35% Margin Cap)**: На одну позицию не может быть выделено более `35%` доступного эквити, чтобы исключить каскадную ликвидацию.
   - **Глобальный Стоп-Кран (24h Rolling Drawdown Kill-Switch -5.0%)**: При достижении скользящей суточной просадки `-5.0%` торговля мгновенно блокируется на 24 часа, все активные лимитные ордера снимаются.
   - **Spread Guard (`0.25%`)**: Блокировка рыночных входов во время прострелов стакана, если спред между Best Ask и Best Bid превышает `0.25%`.
   - **Funding Guard (`15 минут`)**: Запрет открытия позиции в сторону уплаты высокого фандинга (`>= 0.05%`), если до клиринга на бирже осталось менее `15 минут`.
   - **Stale Signal Guard (`30%`)**: Отклонение сигнала из Telegram/новостей, если цена уже ушла более чем на `30%` пути к первому тейк-профиту (`TP1`).
   - **Dynamic TP Dust Collapse**: Если долевое закрытие позиции (`TP1 40% / TP2 40% / TP3 20%`) создает микро-ордер меньше биржевого лимита `minNotional * 1.1` (`$5.50` для Bybit), система автоматически схлопывает доли в 1 или 2 исполняемых ордера, чтобы не оставить «зависший хвост» без тейк-профита.

3. **Каскадная отказоустойчивость ИИ-аналитика (Cascade LLM Fallback)**:
   При генерации аналитического заключения по сигналу система опрашивает провайдеров с жестким таймаутом `7–8 секунд` на каждый уровень:
   1. **Ollama Cloud / Локальный Ollama** (через серверный прокси `/api/ollama/analyze`, обходящий браузерный CORS).
   2. **Google Gemini 2.5 Flash** (облачный резерв 1).
   3. **OpenRouter (`Qwen-2.5-Coder` / `DeepSeek-R1`)** (облачный резерв 2).
   4. **Локальный детерминированный Quant-синтезатор** (мгновенный математический расчет по OBI стакана, VWAP, ставке фандинга и R:R при полной недоступности внешних LLM).

### 1.3. Состав проекта и структура GitHub-репозитория

Все 3 узла системы хранятся в едином монорепозитории GitHub, что позволяет обновлять боевой сервер и домашний тренажер одной командой `git pull`:

* **`/server.ts`** — Центральный серверный шлюз (Node.js / Express):
  * Поддерживает живое подключение к Bybit API v5 (`/v5/market/orderbook`, `/v5/market/tickers`, `/v5/market/kline`), рассчитывает OBI (Order Book Imbalance), Spread bps и латентность RTT.
  * Выполняет реальную подпись `HMAC-SHA256` и отправку ордеров (`/api/bybit/order`).
  * Содержит фоновый скрапер новостей и публичных Telegram-каналов (`t.me/s/<channel>`), криптографически дедуплицирует новости (`SHA-1/ID`), оценивает NLP-сентимент и рассылает алерты в Telegram-бота `@zimatradeai_bot`.
  * Сохраняет все состояние ботов, веса нейросетей, настройки и историю сделок на диск в `/data/runtime_state.json` (файл добавлен в `.gitignore`, чтобы при `git pull` ваши обученные веса и баланс никогда не затирались!).
* **`/src/lib/engine-math.ts`** (и тест `engine-math.test.ts`) — Математическое ядро (`calculateVWAP`, `calculateDynamicTPShares`, `evaluateRiskFirewall`).
* **`/src/lib/bot-learning-math.ts`** (и тест `bot-learning-math.test.ts`) — Квантовое ядро ИИ-Арены (`ONNX_RL`, `LIGHTGBM`, `LLM_SENTIMENT`, `ENSEMBLE`), детектор фазы рынка, онлайн-обучение весов с проекцией на симплекс ($\sum w_i = 1$) и пакетный тренажер эпох на реальных свечах Bybit (`runHistoricalKlineEpoch`).
* **`/src/lib/wallet-math.ts`** (и тест `wallet-math.test.ts`) — Изолированный учет балансов `VIRTUAL` и `REAL`, расчет Sharpe Ratio, Sortino Ratio, Profit Factor, Expectancy и Max Drawdown.
* **`/src/lib/updater-math.ts`** (и тест `updater-math.test.ts`) — Система безопасных OTA-обновлений и контроля памяти (проверяет отсутствие открытых позиций, запас RAM `>= 220 MB`, квоту диска `10 ГБ`, хэш `SHA-256` и статус `Health Check`).
* **`/src/lib/preprod-suite.test.ts`** — Полный 5-уровневый комплекс предрелизных тестов (Unit, Fuzzing, Chaos, Security, Live API E2E).
* **`/src/App.tsx`** — Веб-терминал управления (React 19 + Tailwind CSS + Lightweight Charts).
* **`/.github/workflows/ci.yml`** — Автоматический конвейер **GitHub Actions**, который при каждом `git push` запускает проверку типов TypeScript, все **31 предрелизный автотест** (`npm test`) и контрольную сборку (`npm run build`).
* **`/scripts/deploy-cloudru.sh`** — Однокомандный скрипт установки и безопасного GitHub-обновления на сервере Cloud.ru.
* **`/scripts/train-pc.sh`** — Однокомандный скрипт синхронизации с GitHub и запуска обучения на домашнем ПК.
* **`/zima_trade_ai/trainer_forge/`** — Python-пайплайн глубокого обучения PyTorch PPO+LSTM и экспорта в `.onnx` с криптографическим манифестом `SHA-256`.
* **`/zima_trade_ai/watchdog_cf/worker.js`** — Edge-модуль для **Cloudflare Workers**.

## ЧАСТЬ 2. Выгрузка на GitHub и запуск на 3 узлах (GitOps-процесс)

### 2.0. Как выгрузить этот проект в ваш GitHub-аккаунт

У вас есть **два способа** отправить подготовленный репозиторий на GitHub:

#### Способ А (В один клик через интерфейс AI Studio)
1. В правом верхнем углу окна AI Studio нажмите на иконку **GitHub** (или меню экспорта **Save to GitHub / Export**).
2. Авторизуйте ваш аккаунт GitHub и укажите имя нового репозитория: `zima-trade-ai` (рекомендуется выбрать **Private**, чтобы структура вашей стратегии была видна только вам).

Локальный Git-репозиторий в проекте уже инициализирован, очищен от секретов (через `.gitignore`) и содержит готовый коммит. Чтобы отправить его из терминала:
```bash
git branch -M main
git remote add origin https://<ВАШ_GITHUB_TOKEN>@github.com/<ВАШ_ЛОГИН>/zima-trade-ai.git

```
Сразу после пуша на вкладке **Actions** в вашем GitHub автоматически запустится пайплайн `.github/workflows/ci.yml` и проверит все 31 тест.

В репозитории подготовлен скрипт `scripts/deploy-cloudru.sh`, который берет всю настройку и оптимизацию на себя.

#### Первичная установка на сервер web-app-prod (Ubuntu 24.04 LTS)
Подключитесь к серверу по SSH:
```bash
ssh user1@194.113.34.230
```
И выполните развертывание:
```bash
sudo apt update && sudo apt install -y git curl
```

**Что сделает `bash scripts/deploy-cloudru.sh` автоматически**:
1. Настроит сжатый своп `ZRAM` (`lz4`, `50%` от RAM = `+2.0 ГБ` мягкого буфера без перегрузки vCPU).

#### Как обновлять сервер Cloud.ru при выходе новых версий в GitHub
Когда вы или ИИ внесли изменения в код и запушили их в GitHub, на сервере Cloud.ru достаточно выполнить одну команду:
```bash
cd /opt/zima-trade-ai && bash scripts/deploy-cloudru.sh
```
Скрипт скачает свежий коммит (`git pull --ff-only`), проверит его тестами и перезапустит сервер, **не трогая** ваш файл `.env` и обученные веса в `data/runtime_state.json`.

### 2.2. Узел 2: Запуск на домашнем ПК для обучения ИИ из GitHub (`Trainer Forge` + `Ollama`)

Домашний ПК (с видеокартой NVIDIA RTX / 8+ ГБ VRAM или мощным процессором) не работает 24/7, а включается для дообучения моделей и тяжелого LLM-инференса.

#### Шаг 1. Клонирование репозитория на ПК и запуск единого скрипта обучения
```bash
git clone https://github.com/<ВАШ_ЛОГИН>/zima-trade-ai.git
cd zima-trade-ai

# Запуск цикла обучения (подтянет свежий код из GitHub, обучит эпохи по свечам Bybit и запустит PyTorch тренажер)
bash scripts/train-pc.sh http://<IP_СЕРВЕРА_CLOUD_RU>:3000
```

#### Шаг 2. Что именно выполняет ПК во время обучения:
1. **Квантовое обучение по историческим свечам Bybit (`/api/bots/train`)**:
   Прогоняет реальные свечи `BTCUSDT`, `ETHUSDT`, `SOLUSDT` через все 4 стратегии, корректирует веса `obiWeight`, `momentumWeight`, `vwapWeight`, `sentimentWeight` на вероятностном симплексе ($\sum w_i = 1$) и сразу сохраняет результат в `data/runtime_state.json`. (Также запускается в 1 клик прямо из веб-терминала кнопкой **«Обучить эпоху (Bybit Klines)»**).
2. **Глубокое обучение нейросети PyTorch RL (`PPO + LSTM`) на видеокарте ПК**:
   * `python -m zima_trade_ai.trainer_forge.sync_parquet` — скачивает накопленные архивы стакана с Cloud.ru с лимитом скорости `5 МБ/с` (`ionice -c 3`), чтобы не нагружать боевой сервер.
   * `python -m zima_trade_ai.trainer_forge.train_rl_pytorch` — обучает нейросеть `ActorCritic (LSTM + PPO)` на GPU (`CUDA`).
   * `python -m zima_trade_ai.trainer_forge.export_onnx` — экспортирует веса в `./models/ppo_policy.onnx` и подписывает файл криптографическим хэшем `SHA-256` в `./models/manifest.json`.
   * Вы можете выложить новый `ppo_policy.onnx` и `manifest.json` в **GitHub Releases** вашего репозитория — модуль `updaterGuard.ts` на сервере Cloud.ru проверит совпадение `SHA-256`, убедится в отсутствии открытых сделок и произведет горячую замену модели.
3. **Локальный сервер Ollama на ПК (бесплатная LLM-аналитика)**:
   Запустите на ПК `ollama pull qwen2.5-coder:7b && OLLAMA_HOST=0.0.0.0:11434 ollama serve` и укажите IP вашего ПК в настройках терминала. Запросы пойдут через серверный прокси `/api/ollama/analyze` без ошибок CORS.

### 2.3. Узел 3: Модуль для Cloudflare (`watchdog_cf`) — зачем он нужен и как его задеплоить из GitHub

В репозитории в папке `/zima_trade_ai/watchdog_cf/worker.js` находится специальный модуль для **Cloudflare Workers**. Напоминание о его **3 критически важных задачах** в нашей архитектуре:

1. **Задача №1: Внешний «Dead-Man's Switch» (Сторожевой таймер живучести каждую минуту)**
   * **Зачем нужен**: Если сервер на Cloud.ru зависнет или пропадет связь с дата-центром, сам сервер не сможет отправить вам уведомление о своем падении, а открытые фьючерсные позиции на Bybit останутся без контроля.
   * **Как работает**: Воркер на серверах Cloudflare запускается по расписанию каждую минуту (`* * * * *`) и пингует `/api/system/health` вашего сервера Cloud.ru. Если сервер не ответил 2 раза подряд или цикл стакана завис (`> 5 секунд`), Cloudflare Worker **автономно извне** отправляет экстренную тревогу в ваш Telegram (`@zimatradeai_bot`) и запускает протокол отмены ордеров.

2. **Задача №2: Обход гео-блокировок CloudFront (Bybit API) и Telegram с российских IP Cloud.ru**
   * **Зачем нужен**: Биржа Bybit использует защиту AWS CloudFront, которая периодически блокирует запросы из российских дата-центров (включая Cloud.ru) ошибкой `HTTP 403 Forbidden`, а доступ к `api.telegram.org` с российских хостингов может сбрасываться.
   * **Как работает**: Воркер Cloudflare работает на нейтральных европейских/азиатских узлах (Франкфурт, Амстердам, Сингапур) и служит бесплатным реверс-прокси между вашим сервером Cloud.ru и API Bybit / Telegram.

3. **Задача №3: Защищенный туннель (Cloudflare Zero Trust) и холодный архив R2 (`10 ГБ`)**
   * Закрывает порт `3000` на Cloud.ru от внешнего сканирования и принимает выгрузку старых архивов стакана L2-50 в бесплатные 10 ГБ хранилища **Cloudflare R2**, когда локальная квота на диске Cloud.ru достигает `90%` (контролируется в `updaterGuard.ts`).

#### Деплой модуля Cloudflare из склонированного GitHub-репозитория
```bash
cd zima_trade_ai/watchdog_cf
npm install -g wrangler
wrangler login

# Создайте конфигурацию wrangler.toml
cat << 'EOF' > wrangler.toml
name = "zima-trade-watchdog"
main = "worker.js"
compatibility_date = "2025-02-01"

[triggers]
crons = ["* * * * *"]

[vars]
NODE_A_HEALTH_URL = "https://ВАШ_ДОМЕН_ИЛИ_IP/api/system/health"
TG_ALERT_CHAT_ID = "ВАШ_TELEGRAM_CHAT_ID"
EOF

# Задайте секреты и задеплойте
wrangler secret put TG_ALERT_BOT_TOKEN
wrangler secret put WATCHDOG_SECRET
wrangler deploy
```

## ЧАСТЬ 3. Правила для ИИ при работе с GitHub-репозиторием (Контракт разработки)

Если тебе (ИИ-ассистенту) поручено дорабатывать **ZIMA-TRADE-AI v4.0** из этого GitHub-репозитория, строго соблюдай следующие инварианты:
1. **Защита секретов в Git**: Никогда не коммить реальные ключи API в `.env.example` или исходный код. Файлы `.env` и `data/runtime_state.json` обязаны оставаться в `.gitignore`.
2. **Никакого хардкода и `Math.random()` в торговой логике**: Все котировки берутся из живого Bybit V5, а при сетевом сбое — из детерминированного симулятора с явной меткой `SIMULATED_FALLBACK`.
3. **Неприкосновенность `evaluateRiskFirewall()`**: Любые новые стратегии или внешние сигналы обязаны проходить через `evaluateRiskFirewall()` в `/src/lib/engine-math.ts` и `calculateDynamicTPShares()`.
4. **Симплекс весов ботов**: Сумма весов `obiWeight + momentumWeight + vwapWeight + sentimentWeight` любого бота в `/src/lib/bot-learning-math.ts` всегда должна равняться `1.0000` (`100%`).
5. **Обязательная проверка перед `git commit / git push`**: Перед любым коммитом выполняй `npm test` (все 31 тест в `engine-math.test.ts`, `bot-learning-math.test.ts`, `wallet-math.test.ts`, `updater-math.test.ts`, `preprod-suite.test.ts` должны проходить успешно), `npm run lint` и `npm run build`, чтобы пайплайн GitHub Actions (`.github/workflows/ci.yml`) всегда оставался зеленым.
