# Зафиксированные архитектурные решения (ADR)

- **ADR-001 (Single Execution Owner):** Реальным исполнением ордеров и сверкой состояния на OKX владеет исключительно TypeScript-контур (`server.ts` + `okx-execution-service.ts`). Python-контур (`zima_trade_ai`) принудительно изолирован в `SHADOW` и исследовательский режим.
- **ADR-002 (Single OKX Account + Virtual Portfolios):** Используется один основной аккаунт OKX без физических субаккаунтов. Разделение капитала между ботами реализуется через виртуальные портфели.
- **ADR-003 (Strict OKX Data & Specs in LIVE):** В режиме `LIVE` при `ACTIVE_EXCHANGE=OKX` отключены любые резервные источники котировок (Bybit, MEXC) и синтетические свечи; отсутствие свежих данных или спецификации инструмента полностью блокирует новые входы.
- **ADR-004 (DCA = OFF):** Автоматическое усреднение убыточных позиций и сетки `SO1/SO2` полностью отключены на уровне конфигурации, API и торгового цикла. Разрешены только TP, частичная фиксация, безубыток и trailing stop.
- **ADR-005 (Shadow-Only Learning):** Алгоритмы обучения не имеют права автоматически менять параметры работающих стратегий; кандидаты оцениваются отдельно в Shadow-контуре.
- **ADR-006 (Safe Startup Reconciliation & ORPHANED Policy):** После рестарта новые входы блокируются до сверки с OKX. Неизвестные биржевые позиции не закрываются автоматически, а маркируются `ORPHANED` с блокировкой новых входов по соответствующему символу.
